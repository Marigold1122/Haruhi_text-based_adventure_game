〇、技术架构基调
                                                                                                                        
  本游戏采用酒馆生态兼容架构：                           
                                                                                                                        
  - 角色定义：使用 Character Card V2 spec（PNG 嵌入 JSON 或纯 JSON 均支持）                                             
  - 世界设定/资料注入：使用 SillyTavern World Info / Lorebook 格式（关键词触发 + constant 条目 + 递归触发 + 优先级）
  - 场景化 Prompt 路由：使用酒馆的 Preset（System Prompt 模板组）+ Author's Note（高优先级临时注入）机制                
  - 长期记忆：使用酒馆 Summary 扩展同款机制——完整聊天历史 + 滚动摘要,大窗口模型直接喂完整历史                           
  - 数据格式严格遵循酒馆社区事实标准,使存档与社区内容互通,可直接导入他人做的凉宫春日角色卡与世界书作为素材或扩展        
                                                                                                                        
  游戏壳子（你要写的代码）只负责：                                                                                      
  1. 时间推进与流速控制                                                                                                 
  2. 世界状态变量管理（春日满足度、各 NPC 关系等）                                                                      
  3. 事件触发判定与路由                                  
  4. 事件链状态机                                                                                                       
  5. UI 交互（消息流、选项、双视角切换、自定义输入）
  6. 把以上所有信息按酒馆方式拼成 prompt 喂给 LLM                                                                       
                                                                                                                        
  核心原则：能用酒馆现成机制就不要自己造,代码主要起调度和润滑作用。                                                     
                                                                                                                        
  一、游戏核心概念                                                                                                      
                                                                                                                        
  - 参考《凉宫春日》系列原作（忧郁、叹息、烦闷、消失、暴走、动摇、阴谋、愤慨、分裂、惊愕、直观）的设定与叙事风格,模仿《 
  人生重开模拟器》的渐进式叙事玩法                       
  - 以北高（北口高校）为主舞台,围绕 SOS 团展开校园+超自然双层故事                                                       
  - 按时间线推进,玩家在关键节点进行选择,但绝大多数推进无需选择,日常感为底色                                             
  - 高度依赖 LLM 驱动剧情——LLM 让角色拥有真实命运,代码与酒馆机制是润滑剂                                                
                                                                                                                        
  二、模式系统                                                                                                          
                                                                                                                        
  1. 原作模式                                            

  - 玩家可选 SOS 团成员或相关人物（春日、长门、朝比奈、古泉、阿虚、谷口、国木田、朝仓、佐佐木、橘京子、周防九曜等） 
  - 关键事件应为原著中的真实事件，但仅限关键事件点，其余环节保留高自由度    
  - 每个可玩角色对应一张 Character Card V2,内容包括 description / personality / scenario / first_mes / mes_example /
  system_prompt / 个性化 post_history_instructions                                                                      
  - 角色卡的 scenario 字段写入当前处境、人际关系、阵营立场、未来变数,使 LLM 能符合原作风味展开
  - 预设角色起点必须在其关键事件之前：                                                                                  
    - 长门：从被派遣初期开始                                                                                            
    - 阿虚：从入学北高第一天开始                                                                                        
    - 佐佐木：从与阿虚同初中时期开始                                                                                    
                                                                                                                        
  2. 随机模式                                                                                                           
                                                                                                                        
  - LLM 根据出身、性格随机生成一张新的角色卡（同样符合 V2 spec,可导出供二次使用）                                       
   
  3. 不同起点                                                                                                           
                                                         
  - 提供多个时间线起点,每个起点对应一份默认世界书 + 一份默认 Preset：                                                   
    - 春日转入北高之前
    - 北高入学日（原作起点）                                                                                            
    - SOS 团刚成立                                                                                                      
    - 各成员加入后                                                                                                      
    - 暑假节点（孤岛、漫无止境的八月）                                                                                  
    - 文化祭前后                                                                                                        
    - 消失分支（12 月 18 日）                                                                                           
    - 佐佐木一派出现后                                                                                                  
  - 不同起点切换时,游戏自动加载对应世界书与 Preset                                                                      
                                                                                                                        
  三、身份系统                                                                                                          
                                                                                                                        
  按对超自然世界的卷入程度划分：                                                            
                                                         
  - 路人学生：完全不知情                                                                                                
  - SOS 团边缘人物：被春日选中或自愿接近                 
  - SOS 团核心成员：完全卷入                                                                                            
  - 异常存在：外星人/未来人/超能力者/反 SOS 团方                                                                        
  - 观察者/操控者：高难度,如神人、思念体另一派系                                                                        
                                                                                                                        
  身份决定世界书条目的可见性与触发条件——例如"闭锁空间详细机制"条目对路人玩家关闭,对核心成员开启。身份变化通过事件铺垫渐 
  进推进,不靠死板数值判定。                                                                                             
                                                                                                                        
  四、世界状态系统                                       

  - 春日"无聊度/满足度"是隐藏全局变量,过高触发闭锁空间、神人、世界改变事件链                                            
  - 玩家选择通过 NPC 反馈影响春日心情
  - 世界状态变量在每次拼 prompt 时作为 Author's Note 高优先级注入,LLM 总能感知当前世界紧张程度                          
  - 重大选择可能导致：世界重置、平行分支、SOS 团解散、长门系统暴走                                                      
                                                                                                                        
  五、时间推进机制                                                                                                      
                                                                                                                        
  流速分段                                                                                                              
   
  - 入学前/小学初中：1 次 1 月                                                                                          
  - 入学初期：1 次 2 周                                  
  - SOS 团活跃期/学期中：1 次 1 周                                                                                      
  - 事件链中：流速由事件链自身控制                                                                                      
  - 假期：1 次 1 周                                                                                                     
  - 考试前/毕业前：1 次 1 月                                                                                            
                                                                                                                        
  每次切换流速时给沉浸式文本提示。                                                                                      
                                                         
  操作交互                                                                                                              
                                                         
  - 直接点击中央消息流推进,无独立"下一周"按钮                                                                           
  - 每次推进时,游戏壳子根据当前年龄/身份/季节/世界状态/历事调度对应 Preset + 世界书子集 + Author's Note,然后调用 LLM
                                                                                                                        
  六、事件系统                                           
                                                                                                                        
  1. 触发频率                                            

  - "随机数 + 固定基础概率"决定,不由 AI 自主决策是否触发                                                                
  - 不同身份、时期、世界状态调整基础概率
  - 大量"无需选择的纯叙述事件"穿插,推进世界、影响关系、增加风味                                                         
                                                                                                                        
  2. 事件类型 → Preset 路由                                                                                             
                                                                                                                        
  每种事件类型对应一个酒馆 Preset（不同 system prompt + 不同采样参数 + 不同 Author's Note 模板）：                      
  - 日常事件 Preset
  - 校园事件 Preset                                                                                                     
  - 人际事件 Preset                                      
  - 奇遇事件 Preset                                                                                                     
  - 超自然事件链 Preset                                  
  - 季节性事件 Preset                                                                                                   
                     
  不同身份下事件池差异巨大——路人玩家不会触发"闭锁空间"。                                                                
                                                                                                                        
  3. 事件链
                                                                                                                        
  - 复杂事件用事件链承载,游戏壳子用状态机管理事件链进度                                                                 
  - 渐进式生成：选择题逐个生成,根据前面选择规划后续；开始时让 AI 规划"本事件链共 N 节,在第 N 节给出结束标记"
  - 进入事件链时,壳子切换到对应事件链 Preset,并临时启用相关世界书条目子集                                               
  - 触发方式两种,减少纯随机：                                                                                           
    a. 世界状态推动：春日满足度过低 → 闭锁空间                                                                          
    b. 故事推动：剧情发展到需要 SOS 团出动                                                                              
  - 已具一定身份的角色更难被随机小事件卷入,关键事件链命中率更高                                                         
                                                                                                                        
  4. 关键事件链建议                                                                                                     
                                                                                                                        
  - 闭锁空间-神人讨伐                                                                                                   
  - SOS 团活动事件链（寻找三人组）
  - 棒球大会                                                                                                            
  - 孤岛事件                                                                                                            
  - 文化祭电影拍摄                                                                                                      
  - 消失事件链                                                                                                          
  - 漫无止境的八月（事件链内嵌套循环）                                                                                  
  - 佐佐木一派对峙
                                                                                                                        
  每个事件链对应一个独立 Preset,且关联一组专属世界书条目（参考原作小说片段直接做成世界书内容）。                        
                                                                                                                        
  七、角色卡使用规范                                                                                                    
                                                         
  - 可玩角色：每人一张 V2 角色卡,起点情境写在 scenario,关键人际关系写在 description,说话风格示例写在 mes_example        
  - NPC：班级同学、家人、对立阵营成员等也做成轻量角色卡（缩减字段）,在涉及该 NPC 的事件中作为附加 prompt 注入
  - 角色卡 system_prompt / post_history_instructions 字段在路由时与全局 Preset 合并                                     
  - 完全兼容酒馆 V2 spec,可导入社区现成卡,也可导出自己生成的卡                                                          
                                                                                                                        
  八、世界书使用规范                                                                                                    
                                                                                                                        
  游戏自带一份主世界书（hsuzumiya_lore.json），包含：                                                                   
   
  - constant 条目（永远注入）：SOS 团基本设定、北高校园、当前年代背景                                                   
  - 关键词触发条目：神人、闭锁空间、信息统合思念体、时间平面、超能力者协会、未来人组织、朝仓事件、文艺部部室、电脑研究部
  、北高棒球场……                                                                                                        
  - 身份门控：路人玩家关闭"超自然真相"类条目；核心成员开启全部
  - 事件链专属世界书：进入对应事件链时临时挂载（如"闭锁空间机制详解"仅在该事件链中激活）                                
                                                                                                                        
  世界书条目内容直接引用或改写原作小说原文片段,使 LLM 能在合适时机精准还原原作设定与术语。                              
                                                                                                                        
  支持导入社区现成的凉宫春日世界书叠加。                                                                                
                                                         
  九、Prompt 拼装顺序（酒馆标准）                                                                                       
                                                         
  每次调用 LLM,游戏壳子按以下顺序拼装 prompt（与酒馆默认一致）：                                                        
                                                         
  1. 当前 Preset 的 System Prompt（按事件类型路由)                                                                      
  2. 角色卡的 description / personality / scenario       
  3. 世界书 constant 条目 + 当前激活的关键词触发条目                                                                    
  4. 角色卡 mes_example（few-shot）                                                                                     
  5. 完整聊天历史 / 历事记录（大窗口模型直接喂完）                                                                      
  6. Summary（超长时启用滚动摘要）                                                                                      
  7. Author's Note（最高优先级,注入当前世界状态、身份、年龄、流速阶段、当前事件链状态）                                 
  8. 角色卡 post_history_instructions                                                                                   
  9. 当前用户输入 / 时间推进信号                                                                                        
                                                                                                                        
  完整上下文必须包括前面所有触发的事件、选项、后果——大窗口模型直接全塞,避免同质化重复的根本手段。                       
                                                                                                                        
  十、AI 驱动核心设计                                                                                                   
                                                         
  1. Prompt 路由（核心架构）                                                                                            
                                                         
  - 代码层做路由：根据年龄段、身份、情境类型、世界状态、是否在事件链中,调度对应的 Preset + 世界书子集 + Author's Note   
  模板
  - 这是类 agent 的规划设计,也是项目的核心代码价值                                                                      
                                                                                                                        
  2. 自定义输入
                                                                                                                        
  - 每次出现选项时,提供"自定义输入"选项,玩家文本提交后作为 user message 直接进入对话流,LLM 据此生成后果                 
  - 酒馆原生就是这种交互,完全契合
                                                                                                                        
  3. 早期不要轻易触发事件链                                                                                             
                                                                                                                        
  - 故事基本背景没展开就触发事件链会出戏,前期保持日常铺垫,事件链触发条件需要更严格                                      
                                                         
  4. 盖棺定论用完整历史                                                                                                 
                                                         
  - 结局小传调用 LLM 时,把完整聊天历史全塞进去,不要只用摘要                                                             
                                                         
  十一、UI/交互设计                                                                                                     
                                                         
  单视角模式                                                                                     
   
  - 显示第三人称叙述视角（旁白视角）                                                                                                                                             
                                                                                                                        
  操作                                                                                                                  
                                                                                                                        
  - 中央消息流点击推进                                                                                                  
  - 选项区附"自定义输入"框                               
  - 侧栏显示关系/状态面板,但不强调数据,数据是 AI 工具与触发器                                                           
                                                                                                                        
  十二、结局系统                                                                                                        
                                                                                                                        
  - 替换"死亡":渐进式"故事终结"——好感度崩盘 / 被春日除名 / 转学 / 被回收 / 世界重置等                                   
  - 渐进触发参照人生重开死亡设计：事件1 → 事件2 概率提升 → 事件3 直接终结
  - 体质/属性 + 世界状态 + 春日满足度综合算每周终结概率                                                                 
  - 终结后调用 LLM,完整历事记录全塞,生成"历史"                                                                          
  - 不同结局类型：毕业终章、消失分支永居、闭锁空间牺牲、被回收、世界重置遗忘等                                          
                                                                                                                        
  十三、需要规避的坑                                                                                                    
                                                                                                                        
  1. 不要过分强调数据,数据是 AI 工具与触发器,事件意义在剧情推进                                                         
  2. 不要每次推进都强制选择,大多数应是纯叙述             
  3. 不要每个事件只两个死板选项,LLM 多样选项 + 自定义输入                                                               
  4. 不要不喂完整上下文——大窗口模型一定要塞满相关历事                                                                   
  5. 不要让事件触发太刻板,超自然事件应由世界状态或剧情推动                                                              
  6. 不要让身份升级靠数值死判,需要事件铺垫                                                                              
  7. 不要前期就触发重大事件链                                                                                           
  8. 不要让路人玩家触发核心成员才有的事件                                                                               
  9. 预设角色不要从其关键事件后开始                                                                                     
  10. 不要重复造酒馆已有的轮子——角色卡、世界书、Preset、Summary 全部直接复用其格式与拼装逻辑                            
                                                                                                                        
  十四、开发起步要求                                                                                                    
                                                                                                                        
  1. 阅读并实现 Character Card V2 spec（参考 GitHub 上 malfoyslastname/character-card-spec-v2 仓库的 README）           
  2. 阅读 SillyTavern 世界书机制（参考 SillyTavern 仓库 docs/usage/core-concepts/worldinfo.md）
  3. 获取《凉宫春日》系列原作小说权威文本,用于：                                                                        
    - 提取风格示例填入角色卡 mes_example                                                                                
    - 切片做成世界书条目内容                                                                                            
  4. 搭建路由架构骨架要详细完善,而非占位                                                                                
  5. 实现核心循环：时间推进信号 → 触发判定 → 选定 Preset + 世界书子集 + Author's Note → 拼 prompt（按酒馆标准顺序）→ LLM
   → 选项/叙述 → 完整记录回写
